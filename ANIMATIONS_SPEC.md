# Спецификация анимаций для Rust4ui (v1.0)

## 1. Контекст и философия проекта

**Rust4ui** — это движок для создания десктопных интерфейсов на Rust + egui, где UI описывается декларативно через JSON-файлы. Основные принципы:
- **Отсутствие перекомпиляции**: интерфейс меняется через правку JSON.
- **Легковесность**: рантайм egui без браузерного оверхеда.
- **Декларативность**: интерфейс — это данные, а не код.

**Цель текущей спецификации** — внедрить в Rust4ui систему анимаций, аналогичную **jQuery.animate()**, но адаптированную под нативный рендеринг egui. Мы не пишем сложный физический движок. Мы даем разработчику (или ИИ-агенту) простой и мощный инструмент: **«скажи, какое свойство и как должно измениться за время, и движок сделает это плавно»**.

## 2. Архитектура системы анимаций

Вся система строится на трех китах:

### A. Менеджер анимаций (AnimationManager)
- Глобальный синглтон (или структура, живущая в `AppState`), который хранит все активные анимации в виде `HashMap<AnimId, AnimationTask>`.
- Вызывается в методе `update()` приложения каждый кадр.
- Получает дельту времени (`dt`).
- Обновляет состояния и **помечает виджеты для перерисовки** (через `ctx.request_repaint()`), если анимация активна.

### B. Задача анимации (AnimationTask)
Структура, содержащая всю информацию о конкретном анимационном процессе:

```rust
pub struct AnimationTask {
    pub id: String,                    // Уникальный ID для отслеживания
    pub target_id: String,             // ID виджета (можно использовать путь в JSON)
    pub property: AnimProperty,        // Что анимируем (Fill, Scale, Opacity, TranslateX и т.д.)
    pub start_value: f32,              // Значение в момент старта
    pub end_value: f32,                // Конечное значение
    pub start_time: f64,               // Время старта (в секундах от начала работы приложения)
    pub duration: f32,                 // Длительность в миллисекундах
    pub easing: EasingFunction,        // Функция плавности
    pub on_complete: Option<Action>,   // (Опционально) действие после завершения
}
```

### C. Регистрация виджетов как анимируемых (Animatable)

Каждый виджет (Button, Panel, Label и т.д.) должен реализовать трейт `Animatable` или иметь метод `apply_animation(&mut self, property: AnimProperty, value: f32)`, который обновляет его внутреннее состояние при получении нового значения.

## 3. Формат описания анимаций в JSON

Анимация описывается в том же JSON-файле, что и UI, внутри блока `_animations`.

### 3.1. Базовый синтаксис (как в jQuery)

```json
{
  "type": "Button",
  "text": "Нажми меня",
  "fill": "#3366CC",
  "scale": 1.0,
  "_animations": {
    "on_click": [
      {
        "property": "fill",
        "to": "#FF5500",
        "duration_ms": 300,
        "easing": "ease_out_quad"
      },
      {
        "property": "scale",
        "to": 0.95,
        "duration_ms": 150,
        "easing": "ease_in_quad"
      }
    ],
    "on_hover": [
      {
        "property": "scale",
        "to": 1.05,
        "duration_ms": 200,
        "easing": "ease_out_back"
      }
    ]
  }
}
```

### 3.2. Триггеры и варианты использования

| Триггер (`key`)   | Описание                                                                                                       | Пример из jQuery               |
|:----------------- |:-------------------------------------------------------------------------------------------------------------- |:------------------------------ |
| `on_click`        | Запускается при клике на виджет.                                                                               | `$(el).click(...)`             |
| `on_hover`        | Запускается при наведении курсора (mouse enter). Анимация отката при `mouse leave` описывается в `on_unhover`. | `$(el).hover(...)`             |
| `on_unhover`      | Запускается, когда курсор покидает виджет.                                                                     | `$(el).mouseleave(...)`        |
| `on_appear`       | Срабатывает один раз при появлении виджета (монтировании).                                                     | `$(el).fadeIn()`               |
| `on_disappear`    | При удалении виджета (или закрытии окна).                                                                      | `$(el).fadeOut()`              |
| `on_state_change` | Запускается при изменении связанной переменной в `state` (например, `$state.theme`).                           | Слушатель изменения состояния. |

### 3.3. Свойства (`property`) для анимации

Мы начинаем с базовых, но система должна быть расширяемой через `enum`:

- **Визуальные атрибуты**: `fill` (цвет фона), `stroke` (цвет обводки), `text_color`, `opacity` (прозрачность).
- **Геометрические**: `scale` (масштаб), `translate_x`, `translate_y`, `rotate` (поворот), `corner_radius` (скругление).
- **Сложные**: `shadow_blur` (размытие тени), `shadow_color`.

### 3.4. Easing функции (плавность)

Поддерживаем стандартный набор, аналогичный CSS и jQuery:

| Имя                | Описание                                    |
|:------------------ |:------------------------------------------- |
| `linear`           | Равномерное движение.                       |
| `ease_in_quad`     | Ускорение (въезд).                          |
| `ease_out_quad`    | Замедление (выезд).                         |
| `ease_in_out_quad` | Ускорение и замедление.                     |
| `ease_out_back`    | "Перелет" с возвратом (пружинистый эффект). |
| `ease_out_elastic` | Упругая пружина.                            |
| `bounce`           | Подпрыгивание.                              |

## 4. Техническая реализация (Инструкция для код-агента)

Агенту (ИИ) необходимо модифицировать код в `src/` следующим образом:

### Шаг 1: Создать модуль `animation.rs`

В папке `src/` создай файл `animation.rs`. В нем опиши:

```rust
// 1. Перечисление свойств
#[derive(Clone)]
pub enum AnimProperty {
    Fill, Scale, Opacity, TranslateX, TranslateY, CornerRadius, // ...
}

// 2. Перечисление easing
pub enum Easing {
    Linear,
    EaseInQuad,
    EaseOutQuad,
    EaseInOutQuad,
    EaseOutBack,
    // ... добавить остальные
}

// 3. Структуру задачи
pub struct AnimTask { /* ... поля из спецификации выше ... */ }

// 4. Менеджер анимаций
pub struct AnimationManager {
    tasks: HashMap<String, AnimTask>,
    next_id: usize,
}

impl AnimationManager {
    pub fn new() -> Self { /* ... */ }
    pub fn add_task(&mut self, task: AnimTask) { /* ... */ }
    pub fn update(&mut self, dt: f32, ctx: &egui::Context) {
        // 1. Перебрать все задачи
        // 2. Вычислить прогресс (elapsed / duration)
        // 3. Применить easing
        // 4. Вызвать apply_value на целевом виджете
        // 5. Если прогресс >= 1.0 - удалить задачу
        // 6. Если есть активные задачи -> ctx.request_repaint()
    }
}
```

### Шаг 2: Добавить трейт `Animatable` для виджетов

В `src/widgets/mod.rs` добавь:

```rust
pub trait Animatable {
    fn set_animated_value(&mut self, property: AnimProperty, value: f32);
}
```

Реализуй этот трейт для всех основных виджетов (Button, Panel, Label и т.д.).

**Пример реализации для Button:**

```rust
impl Animatable for Button {
    fn set_animated_value(&mut self, property: AnimProperty, value: f32) {
        match property {
            AnimProperty::Fill => self.fill = value.into(), // конвертация f32 в Color
            AnimProperty::Scale => self.scale = value,
            AnimProperty::Opacity => self.opacity = value,
            _ => {}
        }
    }
}
```

### Шаг 3: Парсинг `_animations` из JSON

В `src/parser.rs` или `src/loading.rs` модифицируй загрузку `UiNode`. При парсинге объекта виджета проверяй наличие ключа `_animations`. Если он есть, сохраняй описание в структуру виджета (поле `pub animations: Option<AnimationDefinition>`).

Алгоритм парсинга:

1. Прочитать `on_click`, `on_hover` и т.д. как векторы объектов.
2. Для каждого объекта прочитать `property` (ожидаем строку и маппить в `AnimProperty`), `to` (f32 или строка с hex цветом, которую парсим отдельно), `duration_ms` (f32), `easing` (строку).
3. Сериализовать это в промежуточный enum `AnimDefinition`.

### Шаг 4: Интеграция в цикл обновления `egui`

В главном `App::update` (где ты вызываешь `ui.render()`) добавь вызов:

```rust
self.animation_manager.update(dt, ctx);
```

После обновления, пройдись по всем анимируемым виджетам и примени к ним новые значения (используя `Animatable`).

## 5. Рекомендации по дизайну для агента

1. **Безопасность**: Если виджет не реализует `Animatable` для запрошенного свойства — игнорируй анимацию и логируй предупреждение (не паникуй).
2. **Производительность**: Для хранения состояний виджетов внутри `AnimationManager` используй `Weak` ссылки или `Id` (путь в JSON), чтобы не держать сильные ссылки и не блокировать загрузку нового UI при хот-релоаде.
3. **Интерполяция цветов**: Если мы меняем `fill` или `stroke`, цвет должен интерполироваться в RGB-пространстве (или HSV для более сочных переходов). Используй готовую функцию `lerp_color(c1, c2, t)`.
4. **Прерывание анимаций**: При новом триггере (`on_click` или `on_hover`) для того же свойства, анимация должна "перехватываться" — не резко обрываться, а плавно начинать новый путь от текущего значения. Для этого перед созданием новой задачи, удали старую для этого виджета и свойства.

## 6. Примеры использования (для демонстрации агенту)

### Простая пульсирующая кнопка

```json
{
  "type": "Button",
  "text": "Пульс",
  "_animations": {
    "on_appear": [
      {
        "property": "scale",
        "from": 0.8,
        "to": 1.0,
        "duration_ms": 400,
        "easing": "ease_out_back"
      }
    ],
    "on_click": [
      {
        "property": "fill",
        "to": "#00FFAA",
        "duration_ms": 100,
        "easing": "linear"
      }
    ]
  }
}
```

### Эффект "Рябь" (Ripple) при клике

Для этого потребуется кастомный виджет, но как базовый трюк: при клике запускаем анимацию `scale` на внутреннем круге (увеличивая его от 0 до 2.0) и одновременно `opacity` от 1.0 до 0.0. Это создаст эффект расходящейся волны.

```json
{
  "type": "CustomRippleButton",
  "text": "Кликни меня",
  "ripple": {
    "_animations": {
      "on_click": [
        { "property": "ripple_scale", "to": 2.0, "duration_ms": 500, "easing": "ease_out_quad" },
        { "property": "ripple_opacity", "to": 0.0, "duration_ms": 500, "easing": "linear" }
      ]
    }
  }
}
```
